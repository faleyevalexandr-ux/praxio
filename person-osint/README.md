# person-osint

Сбор публично доступных сведений о человеке по ФИО с уточнением по городу и месту работы.
Одиннадцать открытых источников, **ни одного API-ключа**, каждый факт со ссылкой на первоисточник
и числовой оценкой достоверности.

```
person-osint "Иван Петров" --city Москва --company "Яндекс"
```

## Что это и чего это не

**Делает:** ищет по имени в открытом вебе, собирает публичные профили, публикации, упоминания
в прессе и структурированные данные (schema.org, Wikidata, ORCID), сводит дубли, оценивает
вероятность того, что находка относится к искомому человеку, и выдаёт отчёт в Markdown и JSON.

**Не делает и не будет:** обход авторизации, парсинг закрытых профилей, перебор паролей,
работу с утёкшими базами, поиск по телефону в серых агрегаторах, определение адреса проживания.
Инструмент видит ровно то же, что видит любой человек в браузере без входа в аккаунт.

## Правовая и этическая рамка

Открытость данных не отменяет требований к их обработке. Прочитайте это до первого запуска.

- **Основание.** ФИО, место работы, город — персональные данные. Их обработка требует законного
  основания: согласия субъекта, договора, законного интереса (GDPR, ст. 6; 152-ФЗ, ст. 6).
  Флаг `--purpose` записывает заявленную цель в отчёт — используйте его, это ваш audit trail.
- **Уместные сценарии:** проверка контрагента перед сделкой, проверка кандидата с его ведома,
  комплаенс и KYC, аудит собственного цифрового следа, поиск публичных данных о публичной персоне.
- **Неуместные сценарии:** слежка за бывшими партнёрами, преследование, скрытое профилирование
  клиентов и пациентов, сбор досье на частных лиц без их ведома. Профилирование пациентов
  медицинских и психологических практик дополнительно затрагивает специальные категории данных
  и почти всегда незаконно.
- **Хранение.** Отчёт — это досье. `.gitignore` уже исключает каталоги `reports/` и `.cache/`.
  Кэш выключен по умолчанию именно потому, что это персональные данные на диске.
- **Право на возражение.** Если человек просит удалить собранное — удалите.

Инструмент соблюдает `robots.txt`, выдерживает паузу между запросами к одному хосту
и честно представляется в `User-Agent`. Не отключайте `--ignore-robots` без причины.

## Установка

Нужен Node.js 20.11 или новее.

```bash
cd person-osint
npm install
npm run build
node dist/cli.js "Иван Петров" --city Москва
```

Для разработки сборка не нужна — Node исполняет TypeScript напрямую:

```bash
npm start -- "Иван Петров" --city Москва --verbose
npm test
```

## Использование

```bash
# базовый сценарий
person-osint "Иван Петров" --city Москва --company "Яндекс"

# академический след, вывод в консоль
person-osint "Ada Lovelace" --country US --format md --stdout

# только быстрые источники, строгий порог
person-osint "Иван Петров" --only websearch,social,github --threshold 0.6

# фиксация основания сбора
person-osint "Иван Петров" --company "ООО Ромашка" --purpose "проверка контрагента по договору №14"
```

`person-osint sources` печатает список источников с их идентификаторами.
`person-osint --help` — полный список опций.

### Ключевые опции

| Опция | Смысл |
| --- | --- |
| `--city`, `--company` | Уточнители. **Без них однофамильцы неотделимы** — инструмент прямо об этом предупредит |
| `--keyword` | Дополнительный маркер (должность, специальность), можно повторять |
| `--threshold` | Порог уверенности для основного раздела отчёта, по умолчанию `0.45` |
| `--only` / `--skip` | Выбор источников по идентификаторам |
| `--cache` | Кэш ответов на диск. Ускоряет повторные прогоны, но оставляет персональные данные в `.cache/` |
| `--no-enrich` | Не догружать найденные страницы (быстрее, но без данных schema.org и связей между профилями) |
| `--format` | `md`, `json` или `both` (по умолчанию) |

## Источники

Все работают без регистрации и ключей.

| ID | Источник | Что даёт |
| --- | --- | --- |
| `websearch` | DuckDuckGo (HTML) | Широкий веб-поиск по имени с уточнителями |
| `social` | DuckDuckGo + `site:` | Прицельный поиск профилей: LinkedIn, GitHub, VK, Telegram, X, Habr, hh.ru, Behance и др. |
| `wikidata` | Wikidata / Википедия | Структурированные факты о публичных персонах |
| `github` | GitHub REST API | Компания, город, сайт, связанные аккаунты (10 запросов/мин без токена) |
| `openalex` | OpenAlex | Научные публикации, аффилиации, ORCID |
| `orcid` | ORCID Public API | Идентификатор исследователя и заявленные им места работы |
| `crossref` | Crossref | Публикации с DOI и аффилиации из метаданных |
| `dblp` | DBLP | Публикации по информатике |
| `news` | Google News RSS | Упоминания в прессе |
| `hackernews` | Algolia HN | Упоминания в обсуждениях |
| `stackexchange` | Stack Overflow API | Публичный профиль: город, сайт, описание |

Ни один источник не является обязательным: отказ любого из них не останавливает прогон,
в отчёте будет отметка об ошибке.

## Как читается отчёт

Каждая находка несёт три вещи: **значение**, **оценку уверенности** и **ссылку на первоисточник**.

- 🟢 `≥ 0.75` — имя совпало и подтвердилось городом, организацией или самозаявленными данными
  (schema.org, поле профиля, ORCID).
- 🟡 `0.45–0.75` — имя совпало, подтверждения контекстом нет или оно частичное.
- ⚪ `< 0.45` — раздел «Требует проверки». Скорее всего, однофамильцы.

Оценка — это результат работы алгоритма, а не факт. **Проверяйте по ссылкам.**
Раздел «На что обратить внимание» в начале отчёта предупреждает об омонимии: если вокруг имени
прослеживается несколько разных контекстов, инструмент сообщит, что это, вероятно, разные люди.

## Как устроено

```
src/
  cli.ts              разбор аргументов, запись отчётов
  config.ts           настройки прогона, реестр площадок
  types.ts            доменная модель (факт без источника невозможен)
  core/
    http.ts           robots.txt, паузы по хостам, ретраи с Retry-After
    robots.ts         разбор robots.txt с приоритетом по длине правила
    limiter.ts        ограничение параллелизма и темпа
    cache.ts          файловый кэш (по умолчанию выключен)
    text.ts           разбор ФИО, транслитерация, сравнение с учётом склонений
    html.ts           Open Graph, JSON-LD schema.org/Person, rel=me
    ddg.ts            клиент поиска
    score.ts          оценка релевантности находки
    merge.ts          слияние дублей и учёт независимых подтверждений
  sources/            одиннадцать источников, у всех общий интерфейс Source
  pipeline/
    run.ts            оркестрация, изоляция отказов
    enrich.ts         догрузка страниц найденных профилей
  report/markdown.ts  человекочитаемый отчёт
```

Как оценивается находка (`core/score.ts`):

1. **Имя — обязательное условие.** Не совпало в тексте или в URL → находка отбрасывается.
2. **Город и организация поднимают оценку** — именно они разделяют однофамильцев.
3. **Площадка даёт поправку**: персональная страница информативнее случайного форума.
4. **Имя в адресе весит меньше имени в тексте.** Если ник совпал, а на самой странице
   человека не видно, уверенность ограничена: ники наследуются, продаются и достаются
   сообществам, названным в честь человека.
5. **Потолок для находок без единого уточнителя занижен принудительно** — это главный
   источник ложных срабатываний.
6. **Независимое подтверждение другим источником повышает уверенность нелинейно**:
   три перепечатки одной новости не делают факт втрое достовернее.

### Добавить свой источник

```ts
import type { Source } from '../types.ts';

export const mySource: Source = {
  id: 'mysource',
  name: 'Мой источник',
  category: 'search',
  description: 'Что он делает',
  needsKey: false,
  async run(ctx) {
    // ctx.names.queryForms — формы имени, ctx.http — клиент с robots.txt и паузами
    return { profiles: [], documents: [], facts: [] };
  },
};
```

Зарегистрируйте его в `src/sources/index.ts`. Скоринг, слияние и отчёт подключатся сами.

## Тесты

```bash
npm test        # 113 тестов, сеть не используется
npm run typecheck
```

Сетевые вызовы в тестах подменяются заготовками (`test/helpers.ts`), поэтому набор
детерминирован и проходит офлайн. Сквозной тест прогоняет весь пайплайн целиком:
от поисковой выдачи до готового Markdown.

## Вынести в отдельный репозиторий

Проект самодостаточен и ничего не берёт из окружающего репозитория:

```bash
git subtree split --prefix=person-osint -b person-osint-only
git push git@github.com:<user>/person-osint.git person-osint-only:main
```

Либо просто скопируйте каталог `person-osint/` — он работает как есть.

## Ограничения

- **Живой прогон против реальных источников не проверялся** в среде разработки: исходящая сеть
  там закрыта политикой прокси. Логика покрыта тестами на заготовках, но вёрстка DuckDuckGo
  и схемы ответов API меняются — первый запуск у себя стоит сделать с `--verbose`.
- DuckDuckGo при частых запросах начинает отдавать пустую выдачу; помогает увеличить `--delay`.
- GitHub без токена ограничен 10 поисковыми запросами в минуту.
- LinkedIn отдаёт роботам заглушку: находится сам факт наличия профиля и его URL, содержимое — нет.
- Инструмент рассчитан на кириллические и латинские имена. Для других письменностей
  транслитерация и разбор ФИО не работают.
